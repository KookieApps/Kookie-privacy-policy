In short: Your data stays on your device unless you deliberately create an account — then a copy is stored in the cloud so it works across your devices and in your family. The app shows no ads and does not sell data. You can turn analytics off in Settings.

01 General information

Kookie is a meal planning app for iOS and Android, created by Łukasz Chochel. This policy explains what data is processed when you use the app and for what purpose.

The developer does not show ads, does not sell user data and does not share it with third parties for marketing purposes.

02 Data stored locally

The app stores the following data only on the user's device:

  • recipes (name, ingredients, instructions, photos)
  • weekly meal plan
  • shopping list and the checked state of its items
  • ingredient dictionary
  • app settings (theme, first day of the week)
  • tutorial progress

Without an account, data stays on the device and is not synced to the cloud. Deleting the app removes the local copy of the data from the device.

The app may send local notifications to your device about planned meals and your shopping list. Notifications are generated entirely on the device from locally stored data. No data is sent to external servers in connection with notifications. You can manage notification permission in the app's Settings and in your phone's system settings.

03 Account, cloud and family

An account is optional. When you sign in with Google (iOS or Android) or Apple (iOS only), Kookie stores in Supabase your email address, the account identifier from the sign-in provider and — if the provider shares it — your display name.

The cloud receives the copy of data needed for the account to work: recipes, ingredients, meal plan, shopping list and its state, planning-related settings, and private notes and ratings. A random installation identifier is used to safely reconcile changes between devices and to count the import limit (section 04), not for advertising or tracking outside Kookie. It is stored in the cloud copy of your data, so other family members can see it too.

If you join a family, its members see and jointly edit the family's data, such as recipes, the plan and the shopping list. Each member keeps their own account and private data.

Where data is stored

Supabase — account and cloud copy of data

Operator: Supabase Inc., USA. Kookie data is stored in the EU region (Frankfurt, Germany). Access to account and family data is limited to the signed-in user and members of their family.

Deleting your account

You can start account deletion in the app's Settings. Deleting the account erases that account's data from the cloud. The owner of an active family must first resolve the family so that other members' data is not deleted. If you cannot access the app, request account deletion via the account deletion form.

04 Recipe import (link, photo, PDF)

Recipe import sends data off the device only when the user pastes a URL, selects a photo or selects a PDF file.

What is sent

  • the URL provided by the user
  • the content of the web page at that address (the recipe text)
  • for photo import — the selected recipe photos
  • for PDF import — the text extracted from the selected file

The app does not send your name, email or location. Together with the URL it sends a random Kookie installation identifier — see “Import limit” below for what it is and why.

How processing works

  • The app sends the URL to an intermediary server.
  • The server fetches the page content directly from its owner.
  • The content is passed to the Claude API (Anthropic) to extract the recipe data.
  • The parsed recipe is returned to the app and saved locally on the device.

Photo and PDF import work the same way: the photos or the file text go through the intermediary server to the Claude API, and the result returns to the app. The server does not store photos, files or their content.

Data processors

Supabase — intermediary server infrastructure

Operator: Supabase Inc., USA. This app's server: EU region (Frankfurt, Germany).

What is logged: technical metadata only — timestamp, HTTP status, execution time, headers. Neither the URL nor the response from Claude is logged or stored by Supabase.

Technical metadata is kept for 1 day and then deleted automatically.

Supabase Privacy Policy →
Anthropic — text processing by the Claude model

Operator: Anthropic PBC, USA / Anthropic Ireland Limited, Ireland (for users in the EEA).

What is processed: the content of the web page containing the recipe, and for photo or PDF import — the photos or the file text.

Content submitted for processing is automatically deleted by Anthropic within 30 days. Under Anthropic's Commercial Terms of Service, data sent through the API is not used to train AI models.

Anthropic Privacy Policy →

Import limit and abuse protection

The number of free imports is limited. To enforce this limit and to prevent mass misuse of the service, the app sends a random Kookie installation identifier with each import. It is an identifier assigned by the app — not a phone number, not an advertising identifier and not a hardware identifier.

The server does not store the identifier itself, only its one-way hash, from which the identifier cannot be recovered. Each import creates an entry: identifier hash, import type, number of recipes, app version and time. The URL and recipe content are not part of this entry.

Entries are kept indefinitely because the limit counter depends on them. If you are signed in, the entry is also linked to your account. After account deletion the entries remain but lose the link to the account.

The installation identifier is also part of the cloud copy of your data (section 03), so other family members can see it.

05 Ingredient nutrition data

When Kookie looks up nutrition data for an ingredient, the ingredient name may be sent to the server. The result is used to complete information in the app. Your email address, library content and account data are not sent.

To protect the service from abuse, the server processes a one-way hash of the IP address. The IP address itself is not stored.

USDA FoodData Central and Anthropic

The ingredient name may be passed to the public USDA database and to Anthropic to find and select the right nutrition data.

06 Analytics

The app collects usage data to understand how it is used and to improve it. No personal data, recipe content or device identifiers are collected.

What is collected (among others)

  • app launch
  • adding a meal to the weekly plan (meal type only — no recipe content)
  • opening the shopping list
  • checking an item on the shopping list
  • importing a recipe from a URL
  • creating a recipe manually

Events are identified by a randomly generated pseudonymous identifier (UUID v4), which is not linked to your identity or device and is permanently removed when the app is uninstalled.

Data processor

PostHog — product analytics

Operator: PostHog Inc., USA. Server region used by this app: EU Cloud (Frankfurt, Germany).

Data is processed only on servers in the EU.

PostHog Privacy Policy →

Opting out

You can turn analytics off at any time in the app: Settings → Privacy → Anonymous analytics. The setting takes effect immediately.

07 In-app purchases (Kookie+)

You buy import packs and the Kookie+ subscription (renewed monthly) through the App Store (Apple) or Google Play. Payment, renewals and cancellation are handled by the store — Kookie does not see card or payer details.

The subscription is tied to your App Store or Google Play account and to the phone it was bought on, not to a Kookie account. A Kookie account is not needed to buy. On another device with the same store account you can transfer the subscription with the “Restore purchase” button.

What is processed

  • a random purchase identifier assigned by Kookie (not an email, not an advertising identifier, not a hardware identifier)
  • transaction data from the store: product, price, currency, date, transaction identifier, store country
  • the balance of purchased imports and their use
  • Kookie+ subscription status: whether it is active, until when, whether it renews, and store events (purchase, renewal, cancellation, expiry, refund)
  • if you are signed in — the link between the balance and your account

Purchase, balance and subscription data is kept while the balance or subscription is active, and for the period required by tax and accounting law. After account deletion, purchases remain with the purchase identifier but lose the link to the account.

Data processors

RevenueCat — confirming and restoring purchases

Operator: RevenueCat, Inc., USA. Receives the purchase identifier, transaction data from the store and basic technical data needed for the service to work (system, app version, IP address).

RevenueCat Privacy Policy →
Supabase — balance and purchase status

Operator: Supabase Inc., USA. Data stored in the EU region (Frankfurt, Germany).

08 Reporting a problem

In Settings you can send a problem report, e.g. about a purchase or an import. The report contains:

  • the category and text of the report
  • an email address for the reply and an order number — only if you provide them
  • diagnostic data: app version, system, purchase identifier, list of transactions and import limit status
  • a one-way hash of the installation identifier and — if you are signed in — the account identifier

The report is saved in Supabase (EU region) and emailed to the developer via Brevo (Sendinblue SAS, France). It is used only to handle the report, e.g. to check or transfer a purchase. Reports are automatically deleted from the database after 12 months.

Brevo — sending the report to the developer

Operator: Sendinblue SAS (Brevo), France. Data processed in the EU.

The server infrastructure used by this app (Supabase and PostHog) is located in the EU region (Frankfurt, Germany).

Processing by Anthropic takes place under SCC through Anthropic Ireland Limited (EEA). RevenueCat processes data under a data processing agreement with SCC. Brevo processes data in the EU.
